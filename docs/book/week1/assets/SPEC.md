# Week 1 book — author spec (read all of it before writing a chapter)

## Who reads this
Danish. Smart adult, comfortable with a computer and a terminal, has NEVER programmed in C++ and may have
little programming experience at all. Assume nothing. Mac (Apple M5, macOS 26, Apple clang 21, CMake 4.4,
Ninja), C++23. The goal of Week 1 is in `goal.md` (repo root): build Game of Life in the terminal
(toroidal grid, ANSI redraw, configurable size and seed), with CMake + doctest tests, and a first
benchmark number (1000×1000 grid, time one step).

## The one rule from CLAUDE.md
The learner hand-codes the challenge. The book may TEACH every mechanism with complete worked examples,
but it must NEVER contain a working implementation of the Week 1 contract functions
(`index_of`, `wrap`, `count_neighbours`, `step`, `random_cells`, `render` in
`phase1-terminal/01-life/src/life.hpp`) nor a complete Life `main`. Teach the shape on a DIFFERENT
problem that is one step away. Specifically:
- Flat 2D indexing: teach with a multiplication table / checkerboard / small image, not Life.
- Wrap-around: teach in 1D (clock face, days of the week, a ring buffer) and show the negative-modulo trap.
- Neighbour stencil + double buffering: teach with a ONE-dimensional cellular automaton (Rule 90 or
  Rule 30 on a wrapping ring of cells, printed one generation per line). It has exactly the same shapes
  (two buffers, swap, wrap, neighbours) without being the 2D answer.
- Life rules may be stated in words and as a table; never as C++.
Chapter 14 gives hint ladders that get CLOSE (formulas in words, which loop goes where, what to test
first) but stops short of pasting the function body.

## Voice and pedagogy
- First principles. Every new idea is motivated by a problem before it is named. Say what the machine is
  actually doing (bytes in memory, the CPU reading instructions) in plain words. No "magic".
- One idea at a time. Introduce a thing, show the smallest complete program that uses it, show its output,
  then widen. Never use a construct before it was explained (see the "allowed by chapter" list). If you
  truly need something early (e.g. `#include`, `int main`), say "take this on trust until chapter N".
- Analogies, then precision. Every analogy is followed by where it breaks.
- Depth over breadth. A chapter is 2,500–5,000 words of prose plus code. Go deep on what matters for
  Week 1; explicitly defer what does not ("classes: week 4").
- Plain English. Short sentences. Define every term the first time (bold it). No jokes that need
  programmer culture. Write "you", not "we".
- Concrete numbers. When you say an int is 4 bytes, show `sizeof` printing 4.
- Every chapter ends with: "Check yourself" (4–8 questions with hidden answers) and "What you can do now".
- Mention the inference twin from goal.md where it is genuine; don't force it.

## Allowed by chapter (do not use a construct before its chapter)
00 nothing yet (orientation only)       01 `#include <print>`, `int main`, `std::println`, `return 0`, comments
02 variables, int/double/bool/char/std::size_t/std::uint8_t, `auto`, `const`, arithmetic, `sizeof`, `static_cast`
03 if/else, comparison/logical ops, while, for, break/continue, nested loops, `std::print`
04 functions (free), parameters, return, declaration vs definition, scope
05 references `T&`, `const T&`, pass by value vs reference, `const` correctness
06 `std::vector`, `.size()`, `[]`, `.at()`, `push_back`, `resize`, construction `v(n, value)`, range-for
07 flat 2D index `y*w+x`, `%`, swap of two vectors (`std::swap`), `using Name = Type;`
08 `std::string` (+=, size, `[]`, `std::to_string`, `std::stoi`), `argc/argv`, `std::mt19937`,
   `std::uniform_real_distribution` (minimal, "deep dive week 5")
09 `std::print` without newline, `std::cout.flush()`/`std::fflush`, ANSI escapes, `std::this_thread::sleep_for`,
   `std::chrono` durations (literals `100ms`), `std::chrono::steady_clock`
10 `#pragma once`, headers, multiple source files, the linker
11 CMake / Ninja / build types / sanitizer flags           12 doctest
13 timing with chrono, Release vs Debug, benchmark discipline
Never in Week 1: classes/structs (say "week 3/4"), pointers/new/delete (weeks 7 and 10; `std::vector` hides them),
templates (except using `std::vector<T>`), exceptions, inheritance, lambdas, iterators beyond range-for.

## HTML contract (copy `assets/TEMPLATE.html`; keep its <head>, <nav>, <main> skeleton exactly)
- File name: exactly the one assigned (e.g. `03-control-flow.html`) in `docs/book/week1/`.
- `<title>NN · Title — C++ from zero to Life</title>`; `<p class="chapter-kicker">Chapter NN</p>`; one `<h1>`.
- Sections are `<h2>`; sub-sections `<h3>`. No `<h4>`+.
- The sidebar, prev/next links and done-checkbox are generated by book.js — do NOT write them.
- Code: `<pre class="code" data-lang="cpp" data-file="name.cpp" data-check="run"><code>…</code></pre>`
  * `data-check="run"`: complete program, compiles with `-std=c++23 -Wall -Wextra` WITHOUT WARNINGS,
    runs in <10 s, exits 0, needs no stdin and no terminal (no sleeps, no ANSI, no argv). DEFAULT.
  * `data-check="compile"`: complete program that compiles warning-free but sleeps/loops/uses argv/ANSI.
  * `data-check="error"`: complete program that MUST fail to compile (teaching an error message). Follow it
    with the real clang error text in a `<pre class="output">` (no data-for) — run clang to get it.
  * `data-check="fragment"`: a snippet that is not a whole program. Use sparingly; prefer whole programs.
  * After a `run` block you SHOULD give `<pre class="output" data-for="name.cpp"><code>…</code></pre>` with
    the EXACT stdout. The checker compares them. Get it right by actually compiling and running.
  * Shell commands: `<pre class="shell"><code>$ clang++ -std=c++23 hello.cpp -o hello\n$ ./hello\n</code></pre>`
    (lines starting with `$ ` are commands; other lines are shown output.)
  * CMake: `<pre class="code" data-lang="cmake" data-file="CMakeLists.txt"><code>…</code></pre>`.
  * ESCAPE `<` as `&lt;` and `&` as `&amp;` INSIDE EVERY <code>. `#include <vector>` → `#include &lt;vector&gt;`.
    `>` may stay as `>`. Inline code in prose: `<code>std::vector&lt;int&gt;</code>`.
- Callouts (use the exact classes; each has a `<span class="label">`):
  `principle` "First principle", `analogy` "Analogy", `twin` "Inference twin", `trap` "Trap",
  `try` "Try it", `note` for anything else.
- Hidden hints/answers: `<details class="hint"><summary>…</summary>…</details>` and `details.answer`.
- Quiz: `<div class="quiz"><div class="q"><p>Q</p><details class="answer">…</details></div>…</div>`.
- ASCII figures for grids: `<pre class="grid-figure">…</pre>` (no highlighting applied).
- Cross-links to other chapters: `<a href="07-flat-grid.html">chapter 7</a>`; to sections: `07-flat-grid.html#row-major`
  (anchor ids are the h2/h3 text lower-cased, non-alphanumerics → `-`, trimmed). Prefer linking to files only.
- Paths in prose are relative to the repo root: `phase1-terminal/01-life/src/life.hpp`.
- No external resources (no CDN, no images from the web). No inline `<style>` or `<script>`.
- Verify your chapter: `python3 tools/book-check.py docs/book/week1/NN-your-file.html` must print 0 problems.

## Running single-file examples
Chapter 0 introduces `tools/run.sh FILE.cpp` (compiles with the right flags into a temp dir and runs).
Chapters may show either `clang++ -std=c++23 -Wall -Wextra x.cpp -o x && ./x` or `tools/run.sh x.cpp`.
Scratch examples live in `scratch/` at the repo root (git-ignored).
