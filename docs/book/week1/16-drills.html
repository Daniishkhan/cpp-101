Drills: write it from an empty file

Every drill on this page is meant to be written from nothing: finish a chapter, open an empty file in scratch/, write the drill, run it, and compare your output with the expected output character by character. Only when it matches — or you are honestly stuck — open the solution and compare the decisions, not just the text.

How to use this page

Budget 10–25 minutes per drill. Do a chapter's drills after finishing that chapter and before starting the next one, so each idea is exercised while it is fresh. If a drill takes you past 30 minutes, stop and reread the section it names rather than peeking at the solution — the solutions are for comparing against your attempt, not for copying.

After chapter 01 · What a program is

Print a haiku

Practices: Statements run top to bottom; one std::println per line of output.

Write a complete program, in a new file haiku.cpp, that prints exactly these three lines and nothing else:

One byte, eight switches.
The cook reads each line in turn.
It never skips one.

Compile it with clang++ -std=c++23 -Wall -Wextra haiku.cpp -o haiku (the compiler must stay completely silent), run it with ./haiku, and check that echo $? prints 0 afterwards. Every character matters: the capital letters, the commas, the full stops. Before you run it, read your three statements top to bottom and say the output out loud; the program must match your prediction.

Stuck? First nudge

You need the same skeleton as hello.cpp: the include, int main(), braces, return 0;. The only difference is that the body holds three statements instead of one, each ending in a semicolon, in the order the lines should appear.

Show the solution 
#include <print>

int main() {
    std::println("One byte, eight switches.");
    std::println("The cook reads each line in turn.");
    std::println("It never skips one.");
    return 0;
}

The whole drill is the skeleton plus three statements, performed first to last like the literal cook working down the recipe. If a line came out wrong, look inside the string literal: between the quotes is the one place where every character, spaces included, is printed exactly as typed.

Print a times-table card

Practices: Placeholders: one string with several {}, values supplied as arguments in order.

Write a program, in a new file seven_times.cpp, that prints the start of the seven times table, exactly like this:

7 x 1 = 7
7 x 2 = 14
7 x 3 = 21
7 x 4 = 28
7 x 5 = 35

Two rules. First, every one of the five statements must use the same string literal, containing three {} placeholders; only the values after the string may change from line to line. Second, remember what the chapter said about "{} plus {} is {}": the program does not do the arithmetic, you do. You type the 14, the 21 and the rest yourself. Predict the output on paper first, then compile with -Wall -Wextra (no warnings allowed) and run.

Stuck? First nudge

Design the string once, with a {} where the 7 goes, a {} where the count goes, and a {} where the product goes, with the x, the = and the single spaces written out between them. Then each statement hands over three values, in the same order as the placeholders.

Show the solution 
#include <print>

int main() {
    std::println("{} x {} = {}", 7, 1, 7);
    std::println("{} x {} = {}", 7, 2, 14);
    std::println("{} x {} = {}", 7, 3, 21);
    std::println("{} x {} = {}", 7, 4, 28);
    std::println("{} x {} = {}", 7, 5, 35);
    return 0;
}

The string "{} x {} = {}" is the template; the first value fills the first {}, the second the second, the third the third. The repetition is deliberately painful: in chapter 3 a loop will produce all five lines from one statement, and in chapter 2 the program will compute the products itself.

Answer a riddle with the exit code

Practices: return sends a value to the shell; echo $? reads it; the value is not printed.

Write a program, in a new file riddle.cpp, that prints exactly these two lines:

Riddle: how many switches make one byte?
I have already answered. Ask the shell: echo $?

and whose exit code is the answer to the riddle. Add a line comment on the return statement saying why that number, not what the statement does. The full check, which you should run yourself, looks like this:

$ ./riddle
Riddle: how many switches make one byte?
I have already answered. Ask the shell: echo $?
$ echo $?
8

One catch from the chapter's hints: run echo $? once, immediately after ./riddle. If you run anything in between, the 8 is gone.

Stuck? First nudge

The chapter showed a program whose main ended with return 3; and what the shell reported afterwards. This is the same shape with a different number, which never appears anywhere in the output, only in the return statement.

Show the solution 
#include <print>

int main() {
    std::println("Riddle: how many switches make one byte?");
    std::println("I have already answered. Ask the shell: echo $?");
    return 8;  // a byte is eight switches, so the answer rides out as the exit code
}

The key realisation is that return 8; prints nothing: the value travels through the operating system to the shell, invisibly, and only echo $? makes it appear. A common wrong turn is printing the 8 as a third line; the task pins the output to two lines precisely so that the answer can only leave through the exit code.

Print a glider card

Practices: Combining everything: placeholders, literal braces via doubling, comments, and commenting out. · warm-up for M2

Game of Life's most famous shape is the glider, five live cells that walk diagonally across the grid. Write a program, in a new file glider_card.cpp, that prints a 5×5 grid holding one glider, with a header line above it, exactly like this:

{w: 5, h: 5, live: 5}
.#...
..#..
###..
.....
.....

Four requirements:

  • The header line must be produced by one statement whose string contains three {} placeholders for the three 5s, and real { and } characters at its ends.
  • The file must open with a block comment saying what the program shows.
  • Somewhere in the body, write a sixth grid-row statement that would print #####, then switch it off with a comment so it does not appear. The output must still be exactly the six lines above.
  • Compile with -Wall -Wextra: zero warnings, and echo $? must print 0 after a run.
Stuck? First nudge

Two different jobs for the same two characters: inside the string, a lone pair of braces is a placeholder that a value fills, while a doubled brace prints itself. Work out the header string by reading it left to right and asking, for each brace in the desired output, which of the two you need. For the switched-off row, either kind of comment works; think about which one can wrap a whole statement mid-file.

Show the solution 
/* glider_card.cpp - a 5x5 grid with a glider, behind a header line.
   The header uses doubled braces so that real { and } appear in the output. */

#include <print>

int main() {
    // Header first, so anyone reading the output knows the grid's shape.
    std::println("{{w: {}, h: {}, live: {}}}", 5, 5, 5);
    std::println(".#...");
    std::println("..#..");
    std::println("###..");
    std::println(".....");
    std::println(".....");

    /* std::println("#####"); */  // a sixth row, switched off on purpose

    return 0;
}

The header string reads "{{w: {}, h: {}, live: {}}}": the doubled braces at the ends print as themselves and the three lone pairs are filled by the three 5s. The most common wrong turn is the very last four characters, {}}}, which the chapter's rules disentangle as one placeholder followed by one doubled closing brace. This hard-coded card is a preview of milestone M2: your render function will produce exactly this kind of dots-and-hashes text, but from cells stored in memory instead of in the source.

Split seconds into a clock readout

Practices: integer division and % split a number into parts; {:02} zero-padding · warm-up for M1

Write a program that starts from one const int holding a number of seconds, 7384, and splits it into hours, minutes and seconds using only / and %. There are 3600 seconds in an hour and 60 in a minute.

Print two lines, exactly:

7384 seconds is 2:03:04
check: 2*3600 + 3*60 + 4 = 7384
  • Minutes and seconds are zero-padded to two digits with {:02}; hours are not.
  • The second line must not hard-code 7384: compute it back from your hours, minutes and seconds variables, so the quotient-times-divisor-plus-remainder identity from the chapter checks your own arithmetic.
  • Every variable that never changes is const.

Before you open the solution, change the starting value to 60 and 3599 and confirm the readout is 0:01:00 and 0:59:59.

Stuck? First nudge

How many whole hours fit in 7384 seconds, and what does % leave behind? Do the split twice: hours out of the total, then minutes out of what was left over. The format code for a two-digit zero-padded number is in the chapter's formatting table.

Show the solution 
#include <print>

int main() {
    const int total_seconds = 7384;

    const int hours = total_seconds / 3600;
    const int rest = total_seconds % 3600;
    const int minutes = rest / 60;
    const int seconds = rest % 60;

    std::println("{} seconds is {}:{:02}:{:02}", total_seconds, hours, minutes, seconds);
    std::println("check: {}*3600 + {}*60 + {} = {}",
                 hours, minutes, seconds,
                 hours * 3600 + minutes * 60 + seconds);
    return 0;
}

The key move is the intermediate variable rest: take the hours out first with / 3600, keep the leftover with % 3600, then split that leftover again by 60. Writing total_seconds / 60 % 60 for the minutes also works, but naming the leftover makes the two-stage split readable. This quotient-and-remainder split is exactly how a flat position turns back into a row and a column in chapter 7.

Print a shop receipt with aligned columns

Practices: double arithmetic, const, and the width/alignment/precision format codes · warm-up for M5

Write a program that prints a small receipt. The items are fixed in the source as const variables: 2 coffees at 32.50 each, 1 rye bread at 24.95, and 3 apples at 4.50 each. Quantities are int, prices are double.

Compute each line total (quantity times unit price), the grand total, and the VAT share. Danish prices already include 25% VAT, so the VAT share of the total is total * 0.20.

The output is exactly:

coffee        2   32.50    65.00
rye bread     1   24.95    24.95
apples        3    4.50    13.50
total                     103.45
of which VAT               20.69

The columns must line up: the name is left-aligned in a field 12 wide, the quantity right-aligned in 3, the unit price right-aligned in 8 with two decimals, and the line total right-aligned in 9 with two decimals. The last two lines put their label in a field 23 wide so the amounts land in the same column. Check your alignment by counting: every line is exactly 32 characters wide.

Stuck? First nudge

One format string, used three times with different values, produces the three item lines. Inside each pair of braces the order is fixed: alignment, then width, then the dot and precision, then f. A string literal can be a placeholder's value too, which is how the name gets its 12-character field. Why 23 for the label on the last two lines? Add up the first three field widths.

Show the solution 
#include <print>

int main() {
    const int coffee_qty = 2;
    const double coffee_price = 32.50;
    const int bread_qty = 1;
    const double bread_price = 24.95;
    const int apple_qty = 3;
    const double apple_price = 4.50;

    const double coffee_total = coffee_qty * coffee_price;
    const double bread_total = bread_qty * bread_price;
    const double apple_total = apple_qty * apple_price;
    const double total = coffee_total + bread_total + apple_total;
    const double vat = total * 0.20;

    std::println("{:<12}{:>3}{:>8.2f}{:>9.2f}", "coffee", coffee_qty, coffee_price, coffee_total);
    std::println("{:<12}{:>3}{:>8.2f}{:>9.2f}", "rye bread", bread_qty, bread_price, bread_total);
    std::println("{:<12}{:>3}{:>8.2f}{:>9.2f}", "apples", apple_qty, apple_price, apple_total);
    std::println("{:<23}{:>9.2f}", "total", total);
    std::println("{:<23}{:>9.2f}", "of which VAT", vat);
    return 0;
}

The quantity times the price mixes an int with a double; the int is widened automatically, so each line total is an exact-looking double with no cast needed. The common wrong turn is putting the amounts in differently sized fields on different lines: the amounts only stack up because 12+3+8+9 on the item lines matches 23+9 on the summary lines. (Real money code uses whole øre in an int, not a double; for a printed receipt with two decimals, double is fine.)

Predict nine traps, then let the machine mark your answers

Practices: negative division and %, unsigned wrap-around, truncation, static_cast re-labelling · warm-up for M3

This drill is done in two halves, and the first half happens on paper. Write down your prediction for each of these nine values before you type any code:

  • a) 100 / 8
  • b) 100 % 8
  • c) -13 / 5
  • d) -13 % 5
  • e) five - 7, where five is a std::size_t holding 5
  • f) static_cast<int>(9.99)
  • g) static_cast<int>(-9.99)
  • h) static_cast<std::uint8_t>(600)
  • i) static_cast<char>(65 + 9)

Then write a program that prints all nine, one per line, labelled a) to i), and mark your own predictions. The exact output to match:

a) 100 / 8  = 12
b) 100 % 8  = 4
c) -13 / 5  = -2
d) -13 % 5  = -3
e) 5 - 7 as std::size_t = 18446744073709551614
f) static_cast<int>(9.99)   = 9
g) static_cast<int>(-9.99)  = -9
h) static_cast<std::uint8_t>(600) = 88
i) static_cast<char>(65 + 9) = J

For every one you got wrong, find the sentence in the chapter that states the rule and say the rule out loud. Seven, eight or nine right first time means the chapter has stuck.

Stuck? First nudge

Each line is one rule from the chapter: division rounds toward zero and the remainder takes the left operand's sign; an unsigned type that goes below zero wraps to its very top; a cast to int truncates, it never rounds; one byte keeps only what is left after taking out whole 256s; and a char is a number wearing a character label, with 'A' at 65.

Show the solution 
#include <cstddef>
#include <cstdint>
#include <print>

int main() {
    std::println("a) 100 / 8  = {}", 100 / 8);
    std::println("b) 100 % 8  = {}", 100 % 8);
    std::println("c) -13 / 5  = {}", -13 / 5);
    std::println("d) -13 % 5  = {}", -13 % 5);

    const std::size_t five = 5;
    std::println("e) 5 - 7 as std::size_t = {}", five - 7);

    std::println("f) static_cast<int>(9.99)   = {}", static_cast<int>(9.99));
    std::println("g) static_cast<int>(-9.99)  = {}", static_cast<int>(-9.99));
    std::println("h) static_cast<std::uint8_t>(600) = {}", static_cast<std::uint8_t>(600));
    std::println("i) static_cast<char>(65 + 9) = {}", static_cast<char>(65 + 9));
    return 0;
}

The two most-missed lines are d) and e). -13 % 5 is -3, not 2: the remainder takes the sign of the left operand, which is precisely why plain % cannot wrap a negative coordinate onto a ring, the "careful with negative numbers" comment next to wrap in the Life stubs. And e) is defined behaviour, so the sanitizers stay silent while 5 − 7 lands on 18,446,744,073,709,551,614 (two below the unsigned top). For h), 600 = 2 × 256 + 88, and one byte keeps only the 88.

Format a benchmark report

Practices: choosing where a division happens (int or double), static-cast thinking, aligned numeric output · warm-up for M7

In chapter 13 you will time Life and fill in a results table. Build the report printer now, with made-up numbers. Start from four const values: width = 1000, height = 1000, steps = 100 (all int), and total_ms = 742.5 (a double: the measured time for all the steps together, in milliseconds).

Compute the cell count, the milliseconds per step, and the throughput in million cells per second (cells per step-millisecond, times 1000 milliseconds per second, divided by a million). Then print exactly:

grid:       1000 x 1000
cells:           1000000
steps:               100
total:           742.500 ms
per step:          7.425 ms
throughput:        134.7 million cells/s

Layout rules: every label is left-aligned in a field 12 wide; every number on the last five lines is right-aligned in a field 12 wide, so the numbers share a right edge; the times use three decimals and the throughput one. On the first line the width is right-aligned in a field 4 wide.

Two things must be true of your arithmetic: no division may lose a fraction it needs (which of your divisions involve two ints?), and changing steps to 1000 must print 0.742 ms per step with nothing else in the code touched.

Stuck? First nudge

Walk through each division asking what type each operand has. total_ms / steps is safe without a cast: one operand is already a double, so the int is widened. The danger would be a cells-per-step-style division between two ints; arrange the computation so a double is involved before any fraction could be thrown away. For the layout, the labels and the numbers each get their own fixed-width field.

Show the solution 
#include <print>

int main() {
    const int width = 1000;
    const int height = 1000;
    const int steps = 100;
    const double total_ms = 742.5;

    const int cells = width * height;
    const double ms_per_step = total_ms / steps;
    const double cells_per_ms = cells / ms_per_step;
    const double million_cells_per_second = cells_per_ms * 1000.0 / 1000000.0;

    std::println("{:<12}{:>4} x {}", "grid:", width, height);
    std::println("{:<12}{:>12}", "cells:", cells);
    std::println("{:<12}{:>12}", "steps:", steps);
    std::println("{:<12}{:>12.3f} ms", "total:", total_ms);
    std::println("{:<12}{:>12.3f} ms", "per step:", ms_per_step);
    std::println("{:<12}{:>12.1f} million cells/s", "throughput:", million_cells_per_second);
    return 0;
}

The load-bearing decision is where each division happens. total_ms / steps and cells / ms_per_step each have a double on one side, so the int is widened and no fraction is lost; writing the throughput as cells / steps-first instead would divide two ints, throw away the fraction, and (with these numbers, 1000000 / 100 = 10000 exactly) even look right until the inputs change. If you prefer to make the widening visible, static_cast<double>(cells) / ms_per_step says the same thing out loud. The benchmark in chapter 13 prints ms per step with this exact {:.3f} shape.

Count the sevens

Practices: a for loop over a range with an if and accumulator variables declared outside the loop

Write a program that looks at every whole number from 1 up to but not including 1000 and gathers three facts about the multiples of 7 in that range: how many there are, what they add up to, and which is the largest. Print the three facts in exactly this form:

multiples of 7 below 1000: 142
their sum: 71071
the largest: 994

Use one for loop and one if. The three counters must be declared before the loop — work out why before you start typing: what happens to a variable declared inside a loop body at the closing brace?

Stuck? First nudge

Three variables before the loop, all starting at 0. Inside the loop, one if asks whether the remainder after dividing by 7 is zero; when it is, each of the three variables gets updated. For the largest, think about the order the loop visits the numbers in: which multiple of 7 is the last one it sees?

Show the solution 
#include <print>

int main() {
    int count = 0;
    int sum = 0;
    int largest = 0;

    for (int i = 1; i < 1000; ++i) {
        if (i % 7 == 0) {
            count = count + 1;
            sum = sum + i;
            largest = i;
        }
    }

    std::println("multiples of 7 below 1000: {}", count);
    std::println("their sum: {}", sum);
    std::println("the largest: {}", largest);
    return 0;
}

The accumulators live outside the loop because the loop body is a block: anything declared inside it is demolished at every closing brace. For largest no comparison is needed — the loop counts upward, so the last multiple it meets is the largest. Note the condition is i < 1000, not <=: the task said below 1000.

Tick, tock, ticktock

Practices: ordering the branches of an if / else if chain when conditions overlap · warm-up for M4

Write a program that prints the numbers 1 to 24, one per line, except that for a multiple of 4 it prints tick instead of the number, for a multiple of 6 it prints tock, and for a number that is a multiple of both it prints ticktock. The exact output is:

1
2
3
tick
5
tock
7
tick
9
10
11
ticktock
13
14
15
tick
17
tock
19
tick
21
22
23
ticktock

Check your output against the line for 12 before you call it done. If your program prints tick there, read the chapter's section on branch order again.

Stuck? First nudge

One for loop, one if / else if / else if / else chain inside it. The chain runs the first true branch and skips the rest — so which question has to be asked first: "multiple of 4?", "multiple of 6?", or "multiple of both?"

Show the solution 
#include <print>

int main() {
    for (int i = 1; i <= 24; ++i) {
        if (i % 4 == 0 && i % 6 == 0) {
            std::println("ticktock");
        } else if (i % 4 == 0) {
            std::println("tick");
        } else if (i % 6 == 0) {
            std::println("tock");
        } else {
            std::println("{}", i);
        }
    }
    return 0;
}

The "both" branch must come first: 12 is a multiple of 4, so if i % 4 == 0 is asked first it wins and ticktock is never reached. A second wrong turn is testing i % 24 == 0 for "both" — the first number divisible by both 4 and 6 is 12, not 4 × 6. This is one of the rare honest uses of <= in a loop header: 24 is a value to visit, not a count of things.

Print a pyramid of stars

Practices: nested loops where the inner loop's bound depends on the outer loop's variable · warm-up for M2

Write a program with a const int height = 5; that prints a centred pyramid of stars, 5 rows tall. The top row has one star; each row below is two stars wider; the bottom row has no spaces in front of it. The exact output (no trailing spaces on any line) is:

    *
   ***
  *****
 *******
*********

Every row is spaces first, then stars. Before you type anything, work out two formulas on paper: for row y (counting from 0), how many spaces, and how many stars? Check both formulas against the top row and the bottom row.

Stuck? First nudge

The chapter's grids used one inner loop per row; here each row needs two, one after the other: a loop that prints the spaces, then a loop that prints the stars, then std::println("") to end the row. Row 0 has 4 spaces and 1 star; row 4 has 0 spaces and 9 stars. What do the two counts have to do with y and height?

Show the solution 
#include <print>

int main() {
    const int height = 5;

    for (int y = 0; y < height; ++y) {
        for (int s = 0; s < height - 1 - y; ++s) {
            std::print(" ");
        }
        for (int star = 0; star < 2 * y + 1; ++star) {
            std::print("*");
        }
        std::println("");
    }
    return 0;
}

The key decision is the two formulas: row y gets height - 1 - y spaces and 2 * y + 1 stars. Two inner loops placed one after the other inside the outer body are just as legal as one nested loop — a loop body is a block and a block holds anything. The common wrong turn is padding the rows on the right as well; the task said no trailing spaces, and your render in the Life project must be equally exact, because the tests compare its output character by character.

Walk round a ring

Practices: while (true) with break, and wrap-around on a 1D ring using the remainder operator · warm-up for M3

A token sits on a ring of 10 cells, numbered 0 to 9, at cell 0. Each move pushes it 3 cells clockwise; past cell 9 it wraps back round to 0 (this is what the remainder operator is for). Write a program that moves the token until it arrives back at cell 0, printing each cell it lands on, then reports how many moves that took. Then do the whole thing again with a step of 4 instead of 3. The exact output is:

step 3: 3 6 9 2 5 8 1 4 7 0
back at the start after 10 moves
step 4: 4 8 2 6 0
back at the start after 5 moves

Note the format: each line of positions starts with step 3: or step 4: and has one space before every number, with nothing after the last. The step-3 walk visits all 10 cells; the step-4 walk comes home after only 5. Both are correct — look at the cells step 4 lands on and say why it can never reach cell 1.

Stuck? First nudge

The awkward part: the token starts at 0, and the loop must stop when it returns to 0 — so a condition checked before the first move would stop the loop before it begins. Which loop shape from the chapter lets you move first and decide to leave afterwards? For the spacing, print " {}" — a space and then the number — with the one tool that stays on the line.

Show the solution 
#include <print>

int main() {
    const int ring = 10;

    std::print("step 3:");
    int position = 0;
    int moves = 0;
    while (true) {
        position = (position + 3) % ring;
        moves = moves + 1;
        std::print(" {}", position);
        if (position == 0) {
            break;
        }
    }
    std::println("");
    std::println("back at the start after {} moves", moves);

    std::print("step 4:");
    position = 0;
    moves = 0;
    while (true) {
        position = (position + 4) % ring;
        moves = moves + 1;
        std::print(" {}", position);
        if (position == 0) {
            break;
        }
    }
    std::println("");
    std::println("back at the start after {} moves", moves);
    return 0;
}

The shape is while (true) with the move at the top and if (position == 0) break; at the bottom: move first, ask after, because the start cell and the stop cell are the same. (position + 3) % ring is the 1D wrap-around idiom — safe here because position + 3 is never negative, which is exactly the trap chapter 7 returns to. Step 4 only ever lands on even cells: 4 shares a factor of 2 with 10, so half the ring is unreachable and the walk comes home early. Having to repeat the whole loop for step 4 should feel clumsy; chapter 4 fixes that with functions.

Measure the distance between two numbers

Practices: Writing small value-returning functions and building one function out of another · warm-up for M1

Write a program with two functions and a main that exercises them.

  • int abs_of(int n) — gives back n with any minus sign removed: abs_of(-7) is 7, abs_of(7) is 7.
  • int distance_between(int a, int b) — gives back how far apart a and b sit on the number line. The distance is never negative, and the order of the arguments must not matter. Build it by calling abs_of; do not repeat the if.

Your main must print exactly this, one std::println per line:

abs_of(9)  = 9
abs_of(-9) = 9
abs_of(0)  = 0
distance_between(3, 10) = 7
distance_between(10, 3) = 7
distance_between(-4, 5) = 9
distance_between(6, 6)  = 0

Before you run it, say out loud what distance_between(-4, 5) computes, step by step.

Stuck? First nudge

A distance is a difference with the sign thrown away. If distance_between computes a - b and hands the result straight to abs_of, its whole body is one return line. For abs_of itself: on which inputs is -n the right answer, and what must happen on every other path? Remember the warning about a path with no return.

Show the solution 
#include <print>

// n with any minus sign removed: abs_of(-7) is 7, abs_of(7) is 7.
int abs_of(int n) {
    if (n < 0) {
        return -n;
    }
    return n;
}

// How far apart a and b sit on the number line. Never negative.
int distance_between(int a, int b) {
    return abs_of(a - b);
}

int main() {
    std::println("abs_of(9)  = {}", abs_of(9));

Stuck? First nudge

Ask one question at a time and return early. When is a the middle one? Exactly when it sits between the other two — and "between" has two orderings, b <= a <= c or c <= a <= b. Show the solution 
#include <print>

// The middle one of the three: not the largest, not the smallest.
// If two or three of them are equal, that shared value is the median.
int median_of_three(int a, int b, int c) {
    if ((b <= a && a <= c) || (c <= a && a <= b)) {
        return a;
    }
    if ((a <= b && b <= c) || (c <= b && b <= a)) {
        return b;
    }
    return c;
}

// Compare what median_of_three gave with what it should have given.
void check_median(int a, int b, int c, int expected) {
    int got = median_of_three(a, b, c);
    if (got == expected) {
        std::println("PASS  median_of_three({}, {}, {}) == {}", a, b, c, expected);
    } else {
        std::println("FAIL  median_of_three({}, {}, {}) gave {}, expected {}", a, b, c, got, expected);
    }
}

int main() {
    check_median(1, 2, 3, 2);
    check_median(2, 3, 1, 2);
    check_median(3, 1, 2, 2);
    check_median(5, 5, 9, 5);
    check_median(9, 5, 5, 5);
    check_median(7, 7, 7, 7);
    check_median(-4, 0, -10, -4);
    return 0;
}

    int wrapped = v[v.size() - 1];           // the last element goes round to the front
    for (std::size_t i = v.size() - 1; i >= 1; --i) {
        v[i] = v[i - 1];                     // walk backwards so nothing is overwritten too soon
    }
    v[0] = wrapped;
}

int main() {
    std::vector<int> ring = {1, 2, 3, 4, 5};
    std::print("start:         ");
    print_all(ring);

    rotate_right(ring);
    std::print("after 1 turn:  ");
    print_all(ring);

    rotate_right(ring);
    rotate_right(ring);
    std::print("after 3 turns: ");
    print_all(ring);

    rotate_right(ring);
    rotate_right(ring);
    std::print("after 5 turns: ");
    print_all(ring);
    return 0;
}

Two traps meet here. Walking forwards copies position 0 into 1, then the new 1 into 2, smearing one value across the whole vector; walking backwards from the end is the fix. And the countdown condition is i >= 1, which a std::size_t can satisfy honestly — i >= 0 would never be false and the first decrement past 0 would wrap to the chapter's enormous number. The v.size() < 2 guard also protects v.size() - 1 from the empty-vector wrap.

Rule 184: traffic on a ring

Stuck? First nudge

For each cell, ask two questions about the old generation only: is there a car here that cannot leave? Is this cell empty with a car behind it, about to drive in? #include <cstdint>
#include <print>
#include <utility>
#include <vector>

void print_road(const std::vector<std::uint8_t>& road) {
    for (std::uint8_t c : road) {
        if (c == 1) {
            std::print("#");
        } else {
            std::print(".");
        }
    }
    std::println("");
}

int main() {
    const int n = 20;
    std::vector<std::uint8_t> current(n, 0);
    std::vector<std::uint8_t> next(n, 0);

    // A traffic jam of five cars, and two more cars further down the road.
    current[3] = 1;
    current[4] = 1;
    current[5] = 1;
    current[6] = 1;
    current[7] = 1;
    current[12] = 1;
    current[13] = 1;

    for (int gen = 0; gen < 10; ++gen) {
        print_road(current);
        // Read ONLY from current, write EVERY cell of next.
        for (int i = 0; i < n; ++i) {
            const std::uint8_t left = current[(i + n - 1) % n];
            const std::uint8_t right = current[(i + 1) % n];
            if (current[i] == 1 && right == 1) {
                next[i] = 1;   // a blocked car stays put
            } else if (current[i] == 0 && left == 1) {
                next[i] = 1;   // the car on the left drives in
            } else {
                next[i] = 0;   // empty road, or a car that just drove off
            }
        }
        std::swap(current, next);
    }
    return 0;
}

Unlike Rule 90, this rule reads the cell itself as well as both neighbours, so updating in place corrupts it even faster: a car would be seen both leaving its old cell and arriving in the new one within a single generation, and cars would duplicate or vanish. The constant 7 cars per line is the cheap invariant that tells you the two-buffer discipline held. Note also the else branch writing 0: a car that drives away must be erased in next, which still holds the generation from two steps ago.

Show the solution 
#include <print>
#include <string>

// Each run of equal characters becomes the character followed by its count.
std::string shrink(const std::string& text) {
    std::string out;
    std::size_t i = 0;
    while (i < text.size()) {
        char current = text[i];
        int count = 0;
        while (i < text.size() && text[i] == current) {
            count += 1;
            i += 1;
        }
        out += current;
        out += std::to_string(count);
    }
    return out;
}

int main() {
    std::println("{}", shrink("aaabbc"));
    std::println("{}", shrink("#####.....#####"));
    std::println("{}", shrink("x"));
    std::println("\"{}\"", shrink(""));
    std::println("{}", shrink("ab"));

    std::string row = "..........####..........";
    std::println("{} -> {} ({} characters down to {})",
                 row, shrink(row), row.size(), shrink(row).size());
    return 0;
}

A uniform number sits in [0.0, 1.0), so six times it sits in [0.0, 6.0), never touching 6. Show the solution 
#include <print>
#include <random>
#include <string>

// One die: a uniform double in [0.0, 1.0) scaled to the six faces 1..6.
int roll(std::mt19937& rng) {
    std::uniform_real_distribution<double> dist(0.0, 1.0);
    return 1 + static_cast<int>(dist(rng) * 6.0);
}

int main() {

    int doubles = 0;
    for (int i = 1; i <= 10; ++i) {
        int a = roll(rng);
        int b = roll(rng);
        std::string line = "roll " + std::to_string(i) + ": " +
                           std::to_string(a) + " " + std::to_string(b);
        if (a == b) {
            line += "  double!";
            doubles += 1;

        std::println("{}", line);

Build a boxed frame string

Practices: building a whole frame as one std::string from parts, sizing a border to its content · warm-up for M2

The function must not print anything itself — the string is the frame, the same shape render has in life.hpp.

  • The box sizes itself to the widest row. Top and bottom edges are +, then dashes, then +. Each text row is |, a space, the text, enough spaces to pad shorter rows out to the widest, a space, |.
  • Every line in the returned string ends with '\n', including the bottom edge.

Your main calls it with the three rows "Game of", "Life", "week 1" and prints the result once. The exact output is:

| Game of |
| Life    |
| week 1  |
+---------+

Stuck? First nudge

Three passes over the rows, all with range-for: one to find the widest, one is hiding inside building the edge, one to append each padded row. For the padding, a loop that starts its counter at the row's size and runs up to the widest appends exactly the missing spaces.

Show the solution 
#include <print>
#include <string>
#include <vector>

std::string boxed(const std::vector<std::string>& rows) {
    std::size_t widest = 0;
    for (const std::string& row : rows) {
        if (row.size() > widest) {
            widest = row.size();
        }
    }

    std::string edge = "+";
    for (std::size_t i = 0; i < widest + 2; ++i) {
        edge += '-';
    }
    edge += "+\n";

    std::string frame = edge;
    for (const std::string& row : rows) {
        frame += "| ";
        frame += row;
        for (std::size_t i = row.size(); i < widest; ++i) {
            frame += ' ';
        }
        frame += " |\n";
    }
    frame += edge;
    return frame;
}

int main() {
    std::vector<std::string> rows = {"Game of", "Life", "week 1"};
    std::print("{}", boxed(rows));
    return 0;
}

Build the edge once and reuse it top and bottom — if the two edges are built separately they drift apart the first time you change one. The padding loop that starts at row.size() and stops at widest is worth staring at: it appends zero spaces to the widest row and exactly the shortfall to every other, with no if needed.

Bounce a ball in a box, on a budget

Stuck? First nudge

Inside the frame-building loops, decide each cell with two questions in order: is this a border cell, and is this where the ball is? The ball question must win. Keep the movement and the bounce test outside the drawing loops, once per frame, and copy the shape of the chapter's paced loop for the timing: a time point before the draw, a subtraction after it.

Show the solution 
#include <chrono>
#include <cstdio>
#include <print>
#include <string>
#include <thread>

int main() {
    using namespace std::chrono_literals;
    using clock = std::chrono::steady_clock;

    const int width = 30;
    const int height = 10;
    const int fps = 25;
    const std::chrono::milliseconds budget(1000 / fps);

    int x = 1;
    int y = 1;
    int dx = 1;
    int dy = 1;

    const auto run_start = clock::now();
    std::print("\x1b[?25l");
    for (int frame = 0; frame < 120; ++frame) {
        const auto frame_start = clock::now();

        // ---- draw: the whole frame is one string ----
        std::string screen = "\x1b[2J\x1b[H";
        for (int row = 0; row < height; ++row) {
            for (int col = 0; col < width; ++col) {
                char cell = ' ';
                if (row == 0 || row == height - 1 || col == 0 || col == width - 1) {
                    cell = '*';
                }
                if (row == y && col == x) {
                    cell = '#';
                }
                screen += cell;
            }
            screen += '\n';
        }
        std::print("{}", screen);
        std::fflush(stdout);

        // ---- move and bounce, once per frame ----
        x += dx;
        y += dy;
        if (x == width - 2 || x == 1) {
            dx = -dx;
        }
        if (y == height - 2 || y == 1) {
            dy = -dy;
        }

        // ---- pace: sleep only for what is left of the budget ----
        const auto spent = clock::now() - frame_start;
        if (spent < budget) {
            std::this_thread::sleep_for(budget - spent);
        }
    }
    std::print("\x1b[?25h");

    const auto total = std::chrono::duration_cast<std::chrono::milliseconds>(clock::now() - run_start);
    std::println("120 frames took {} ms (wanted {} ms)", total.count(), 120 * budget.count());
    return 0;
}

The ball is not stored in any grid: each cell is decided at draw time by comparing (row, col) with (y, x), with the ball test placed after the border test so it wins. The common wrong turn is bouncing at width - 1 and 0 — those are the border cells themselves, so the ball would draw on top of a *; turning at width - 2 and 1 keeps it inside.

    std::vector<int> two(1, 5);
    two.push_back(8);
    CHECK(ring_neighbour_sum(two, 0) == 16);
    CHECK(ring_neighbour_sum(two, 1) == 10);

    std::vector<int> one(1, 7);
    CHECK(ring_neighbour_sum(one, 0) == 14);
}

The key move is (i + n - 1) % n for the left neighbour: adding n first keeps the arithmetic non-negative, so unsigned std::size_t never underflows and % never sees a negative value — the same shape your wrap() will need, where the negative-modulo trap from chapter 7 lives. The tiny-ring checks pin the "count positions, not distinct cells" reading, exactly as the chapter's 2-wide-grid test did in 2D.

Report a benchmark in three units

Practices: converting one measurement between ms per step, ns per cell, cells per second and steps per second, and the napkin check · warm-up for M7

A friend benchmarks their own cellular automaton on a 2000×1000 grid (two million cells) and tells you one number: 2.5 ms per step. ns per cell:      1.250
cells per second: 800.0 million
steps per second: 400.0
napkin check: 400.0 x 2.500 = 1000

The last line is the sanity check from the chapter — steps per second times ms per step must come out as 1000 — and your program must compute it, not just print the text. Check every number by hand before you run.

Stuck? First nudge

Every line is one of the conversions from the units section. Compute seconds per step first; after that, cells per second and steps per second are each a single division. For ns per cell, ask: how many nanoseconds are in one millisecond, and how many cells share them? The format specifiers you need are the ones the chapter's programs used: three decimals, one decimal, and no decimals.

Show the solution 
#include <print>

int main() {
    const double width = 2000;
    const double height = 1000;
    const double cells = width * height;          // 2,000,000 cells
    const double ms_per_step = 2.5;               // the measurement to convert

    const double ns_per_cell = ms_per_step * 1e6 / cells;
    const double seconds_per_step = ms_per_step / 1000.0;
    const double cells_per_second = cells / seconds_per_step;
    const double steps_per_second = 1.0 / seconds_per_step;

    std::println("ms per step:      {:.3f}", ms_per_step);
    std::println("ns per cell:      {:.3f}", ns_per_cell);
    std::println("cells per second: {:.1f} million", cells_per_second / 1e6);
    std::println("steps per second: {:.1f}", steps_per_second);
    std::println("napkin check: {:.1f} x {:.3f} = {:.0f}", steps_per_second, ms_per_step, steps_per_second * ms_per_step);
    return 0;
}

The key decision is to compute seconds_per_step once and derive both throughput numbers from it, so a change to the measurement changes every line consistently. Notice that ns per cell is no longer equal to ms per step here: that equality was a coincidence of the one-million-cell grid, and this grid has two million.

Race index against range-for

Practices: two timed regions in one program, warming up before the clock starts, and using results so the optimiser keeps the work · warm-up for M7

The chapter summed a vector by index. Chapter 6 gave you a second way to visit every element: range-for. Are they the same speed? Write a program, from an empty file, that fills a std::vector<std::uint8_t> of ten million cells with the pattern 1 0 0 1 0 0 … (alive where the index is divisible by 3), then times two separate summing loops: one by index, one by range-for. Before the first clock reading, run one untimed pass of each loop as a warm-up, add both warm-up sums into one variable, and print it. Report both timed sums, both times in ms with three decimals, and the ratio index time divided by range-for time with two decimals.

The three sum lines are your self-check and must read exactly warm-up total: 6666668, sum by index: 3333334 and sum by range-for: 3333334. The timing lines will vary.

What you should see: The three sum lines exactly as pinned in the task, then two timing lines and a ratio. On this machine (Apple M5, Apple clang 21): Debug gave about 41 ms by index against 103-106 ms by range-for (ratio 0.39x); -O2 gave about 0.85-0.97 ms for both, ratio 1.00x.

Stuck? First nudge

You need two timed regions, each bracketed by its own pair of now() readings, so the start and end variables cannot be const — the chapter's loop-order program did the same. The warm-up pass exists so neither timed loop pays the first-touch cost; printing its total also stops the optimiser from deleting it. Ask yourself what must happen to the two timed sums at the end for the same reason.

Show the solution 
#include <chrono>
#include <cstdint>
#include <print>
#include <vector>

int main() {
    const std::size_t n = 10000000;              // ten million
    std::vector<std::uint8_t> cells(n, 0);
    for (std::size_t i = 0; i < n; ++i) {
        cells[i] = static_cast<std::uint8_t>(i % 3 == 0);   // 1 0 0 1 0 0 ...
    }

    // Warm-up: one untimed pass of each loop.
    long long warm = 0;
    for (std::size_t i = 0; i < n; ++i) {
        warm += cells[i];
    }
    for (std::uint8_t c : cells) {
        warm += c;
    }
    std::println("warm-up total: {}", warm);

    // Timed: sum by index.
    auto start = std::chrono::steady_clock::now();
    long long by_index = 0;
    for (std::size_t i = 0; i < n; ++i) {
        by_index += cells[i];
    }
    auto end = std::chrono::steady_clock::now();
    const double ms_index = std::chrono::duration<double, std::milli>(end - start).count();

    // Timed: sum by range-for.
    start = std::chrono::steady_clock::now();
    long long by_range = 0;
    for (std::uint8_t c : cells) {
        by_range += c;
    }
    end = std::chrono::steady_clock::now();
    const double ms_range = std::chrono::duration<double, std::milli>(end - start).count();

    std::println("sum by index:     {}", by_index);
    std::println("sum by range-for: {}", by_range);
    std::println("by index:     {:.3f} ms", ms_index);
    std::println("by range-for: {:.3f} ms", ms_range);
    std::println("index / range-for: {:.2f}x", ms_index / ms_range);
    return 0;
}

On this machine the two builds disagree: in Debug, range-for was about 2.6× slower than indexing (each element access goes through extra checked machinery that the sanitizers make expensive), but with -O2 the two loops compiled to the same machine code and the ratio was 1.00×. That is the trap from the chapter in live form: a Debug measurement would have you "optimising" range-for out of your code for a difference that does not exist in the build you actually measure.

Time push_back against a pre-sized vector

Practices: timing two strategies for the same job, and why a timed result must be used afterwards · warm-up for M7

Chapter 6 gave you two ways to build a vector of five million values: start empty and push_back each one, or construct it at full size with v(n, 0) and assign each slot by index. They produce identical vectors. Do they cost the same?

Write a program, from an empty file, that builds a std::vector<int> holding 0, 1, 2, … 4,999,999 both ways, timing each build separately — the vector's creation belongs inside its timed region, because the question is the full cost of going from nothing to five million filled slots. After both clocks have stopped, sum each vector with a range-for into a long long and print both sums, then both times (three decimals) and the ratio push_back time divided by pre-sized time (two decimals).

Both sum lines must read exactly 12499997500000 — that is your self-check, and using the sums is what forbids the optimiser from deleting either build. Predict the ratio before you run, then run with -O2 three times and take the smallest time for each way.

What you should see: Two identical sum lines of 12499997500000, two timing lines and a ratio. On this machine with -O2, push_back took 6-11 ms against 1.6-3.5 ms pre-sized, a ratio of 3.1x to 3.9x across runs; in Debug the gap was wider, about 4.9x.

Stuck? First nudge

The shape is drill 2 again: two timed regions, one strategy in each, and both results used after the second clock stops. Why does the growing vector cost more than the writes it performs? Think about what must happen to the five million existing elements each time push_back finds no room left, and how many times that happens on the way to five million.

Show the solution 
#include <chrono>
#include <print>
#include <vector>

int main() {
    const std::size_t n = 5000000;               // five million

    // Way A: start empty, grow with push_back.
    auto start = std::chrono::steady_clock::now();
    std::vector<int> grown;
    for (std::size_t i = 0; i < n; ++i) {
        grown.push_back(static_cast<int>(i));
    }
    auto end = std::chrono::steady_clock::now();
    const double ms_grown = std::chrono::duration<double, std::milli>(end - start).count();

    // Way B: make all five million slots up front, then assign by index.
    start = std::chrono::steady_clock::now();
    std::vector<int> sized(n, 0);
    for (std::size_t i = 0; i < n; ++i) {
        sized[i] = static_cast<int>(i);
    }
    end = std::chrono::steady_clock::now();
    const double ms_sized = std::chrono::duration<double, std::milli>(end - start).count();

    // Use both results so the optimiser must keep the work.
    long long sum_grown = 0;
    for (int v : grown) {
        sum_grown += v;
    }
    long long sum_sized = 0;
    for (int v : sized) {
        sum_sized += v;
    }

    std::println("sum (push_back): {}", sum_grown);
    std::println("sum (pre-sized): {}", sum_sized);
    std::println("push_back: {:.3f} ms", ms_grown);
    std::println("pre-sized: {:.3f} ms", ms_sized);
    std::println("push_back / pre-sized: {:.2f}x", ms_grown / ms_sized);
    return 0;
}

The pre-sized build won by 3× to 5× because the growing vector runs out of room again and again, and each growth copies every element it already holds to a fresh, larger block of memory — by five million elements that is around twenty rebuilds. This is why bench_life.cpp creates both grids at full size before the clock starts, and why your Life grids should be built with v(n, 0), never grown cell by cell. A common wrong turn is summing inside the timed regions, which times the check instead of the build.

Predict the Debug penalty on a ring

Practices: the full benchmark skeleton (warm-up, timed block, swap, per-cell units) and reasoning about where a Debug/Release ratio comes from · warm-up for M7

This is bench_life.cpp's whole shape, on a one-dimensional problem. A majority smoother works on a ring of cells: each cell looks at its left neighbour, itself and its right neighbour, and becomes 1 if at least two of the three are 1, otherwise 0. Cell 0's left neighbour is cell n−1 — the wrap from chapter 7.

Write a program, from an empty file, that: makes two vectors of one million std::uint8_t cells; fills the first with the pattern alive-where-i % 7 < 3 (blocks of three alive, four dead); runs 3 warm-up passes and then 20 timed passes between a single pair of clock readings, swapping the two vectors after every pass with std::swap; and finally counts the alive cells and prints the count, the ms per pass and the ns per cell, both with three decimals.

The count line must read exactly alive after 23 passes: 428572 — blocks of three are stable under majority vote, so the pattern survives and the count is the same on every machine. That line is your correctness check and what keeps the optimiser honest.

Then the experiment. The chapter showed a plain sum running about 90× slower in Debug. Each cell here costs four vector accesses but also two % operations and an addition-and-compare. Write down your prediction: will the Debug/Release ratio land above or below 90×, and why? Compile both ways, run each at least twice, and write three sentences: the ratio you measured, whether your prediction held, and which side of the chapter's memory-versus-arithmetic divide this loop sits on.

What you should see: Both builds print the identical line 'alive after 23 passes: 428572'. On this machine Debug gave about 14.1 ms per pass and Release (-O2) between 0.41 and 1.03 ms per pass: a ratio of roughly 14x to 35x, well below the 90x of the plain sum.

Stuck? First nudge

Follow the benchmark's skeleton in order: fill, warm-up loop, first clock reading, timed loop, second clock reading, then the arithmetic. The warm-up loop and the timed loop have identical bodies, and each pass ends with the swap so that what was just written becomes the next input. For the left neighbour, remember the chapter 7 trick: add the ring length minus one and take the remainder, so no index ever goes negative.

Show the solution 
#include <chrono>
#include <cstdint>
#include <print>
#include <utility>
#include <vector>

int main() {
    const std::size_t n = 1000000;               // one million cells on a ring
    std::vector<std::uint8_t> current(n, 0);
    std::vector<std::uint8_t> next(n, 0);
    for (std::size_t i = 0; i < n; ++i) {
        current[i] = static_cast<std::uint8_t>(i % 7 < 3);   // blocks of 3 alive, 4 dead
    }

    const int warmup_passes = 3;
    const int timed_passes = 20;

    for (int pass = 0; pass < warmup_passes; ++pass) {
        for (std::size_t i = 0; i < n; ++i) {
            const std::uint8_t left  = current[(i + n - 1) % n];
            const std::uint8_t right = current[(i + 1) % n];
            const int votes = left + current[i] + right;
            next[i] = static_cast<std::uint8_t>(votes >= 2);
        }
        std::swap(current, next);
    }

    const auto start = std::chrono::steady_clock::now();
    for (int pass = 0; pass < timed_passes; ++pass) {
        for (std::size_t i = 0; i < n; ++i) {
            const std::uint8_t left  = current[(i + n - 1) % n];
            const std::uint8_t right = current[(i + 1) % n];
            const int votes = left + current[i] + right;
            next[i] = static_cast<std::uint8_t>(votes >= 2);
        }
        std::swap(current, next);
    }
    const auto end = std::chrono::steady_clock::now();

    const double total_ms = std::chrono::duration<double, std::milli>(end - start).count();
    const double ms_per_pass = total_ms / timed_passes;

    long long alive = 0;
    for (std::uint8_t c : current) {
        alive += c;
    }
    std::println("alive after {} passes: {}", warmup_passes + timed_passes, alive);
    std::println("ms per pass: {:.3f}", ms_per_pass);
    std::println("ns per cell: {:.3f}", ms_per_pass * 1e6 / static_cast<double>(n));
    return 0;
}
