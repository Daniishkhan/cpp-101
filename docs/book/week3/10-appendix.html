Error decoder

Every message below was produced by Apple clang 21 on this Mac with clang++ -std=c++23 -Wall -Wextra. Read the first line, then the caret.

A struct without its final semicolon

#include <print>

struct Ticket {
    int number = 0;
    int counter = 1;
}

int main() {
    Ticket t;
    std::println("{}", t.number);
    return 0;
}

no_semicolon.cpp:6:2: error: expected ';' after struct
    6 | }
      |  ^
      |  ;
1 error generated.

A struct's closing brace ends a declaration, and every declaration ends with a semicolon. Function bodies do not need one after their brace; structs and enums do. The fix is the one character the caret shows.

Comparing two structs

#include <print>

struct Ticket {
    int number = 0;
    int counter = 1;
};

int main() {
    Ticket a{42, 3};
    Ticket b{42, 3};
    if (a == b) {
        std::println("same ticket");
    }
    return 0;
}

compare_structs.cpp:11:11: error: invalid operands to binary expression ('Ticket' and 'Ticket')
   11 |     if (a == b) {
      |         ~ ^  ~
1 error generated.

"Operands" are the things on either side of an operator. A new type knows no operators at all until you give it some. Either compare the members yourself, or add the one line from chapter 1, bool operator==(const Ticket&) const = default;, inside the struct, which asks the compiler to compare member by member. Point in snake.hpp has exactly that line.

Printing a struct

#include <print>

struct Ticket {
    int number = 0;
    int counter = 1;
};

int main() {
    Ticket t{42, 3};
    std::println("{}", t);
    return 0;
}

In file included from print_struct.cpp:1:
In file included from .../usr/include/c++/v1/print:46:
In file included from .../usr/include/c++/v1/format:211:
.../usr/include/c++/v1/__format/format_functions.h:99:30: error: call to implicitly-deleted default constructor of 'formatter<Ticket, char>'
   99 |       formatter<_Tp, _CharT> __f;
      |                              ^
... (forty more lines of notes)

A long message from deep inside the standard library, which is normal for templates. Do not read it top to bottom. Look for your own type's name: formatter<Ticket, char> means "std::println has no way to turn a Ticket into text". Print the members, or write a function that builds a std::string from the struct and print that. (Teaching std::println to print your type directly is possible, and it is what the test file's printers do for doctest; it needs templates, week 15.)

An enum class used as a number

#include <print>

enum class Light { Red, Amber, Green };

int main() {
    Light now = Light::Amber;
    int code = now;
    std::println("{}", code);
    return 0;
}

enum_as_int.cpp:7:9: error: cannot initialize a variable of type 'int' with an lvalue of type 'Light'
    7 |     int code = now;
      |         ^      ~~~
1 error generated.

This is the protection you asked for: an enum class never turns into a number by itself. When you really want the number (to print it while debugging), say so with static_cast<int>(now). An lvalue, in the message, is just "something with a name and a place in memory", here the variable now.

An optional used as its value

#include <optional>
#include <print>

std::optional<int> first_even(int a, int b) {
    if (a % 2 == 0) {
        return a;
    }
    if (b % 2 == 0) {
        return b;
    }
    return std::nullopt;
}

int main() {
    int found = first_even(3, 8);
    std::println("{}", found);
    return 0;
}

optional_as_int.cpp:15:9: error: no viable conversion from 'std::optional<int>' to 'int'
   15 |     int found = first_even(3, 8);
      |         ^       ~~~~~~~~~~~~~~~~
1 error generated.

An optional might be empty, so the compiler will not let you pretend it is an int. Keep it as a std::optional<int>, check has_value(), then use *found; or use value_or with a fallback (chapter 5).

The terminal's types without their header

#include <print>
#include <unistd.h>

int main() {
    termios saved{};
    tcgetattr(STDIN_FILENO, &saved);
    std::println("saved");
    return 0;
}

no_termios.cpp:5:5: error: unknown type name 'termios'
    5 |     termios saved{};
      |     ^
1 error generated.

termios, tcgetattr and tcsetattr live in <termios.h>; read and STDIN_FILENO in <unistd.h>; poll in <poll.h>; std::signal in <csignal>. The .h headers are not part of C++ but of the operating system's own interface (POSIX), which is why their names have no std::.

Undefined symbols: a source file that is not in the build

#include <print>
#include <string>

std::string latest_message();

int main() {
    std::println("{}", latest_message());
    return 0;
}

Undefined symbols for architecture arm64:
  "latest_message()", referenced from:
      _main in missing_definition-f30757.o
ld: symbol(s) not found for architecture arm64
clang++: error: linker command failed with exit code 1 (use -v to see invocation)

Week 1's linker error, with a new way to cause it. The game is built from three files: if a function's definition is in terminal.cpp and terminal.cpp is missing from the add_executable line (or from your clang++ command for a scratch check), every file compiles and the link fails. The message names the function; find which file defines it, and check that file is in the list.

A switch that missed a case

This one is not an error, it is two warnings, and they are the reason an enum class switch should have no default:

int seconds_of(Light light) {
    switch (light) {
    case Light::Red:
        return 30;
    case Light::Amber:
        return 3;
    }
}

missed_case.cpp:6:13: warning: enumeration value 'Green' not handled in switch [-Wswitch]
missed_case.cpp:12:1: warning: non-void function does not return a value in all control paths [-Wreturn-type]
2 warnings generated.

And if you run it anyway with the sanitizers on and the missing case happens:

missed_case.cpp:5:5: runtime error: execution reached the end of a value-returning function without returning a value
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior missed_case.cpp:5:5

When the switch has a case for every enumerator and each case returns, clang says nothing, because no valid value can reach the end. That is the property you want: add a fourth colour to the enum later, and every switch that forgot it is reported by name.

Two facts worth remembering. A program must be built with -g (every Debug build here is) for lldb to know line numbers and variable names; and with -O0, the Debug default, every variable you wrote really exists, while in a Release build the optimiser may have removed it. And when a sanitizer finds a bug in a program running under lldb, lldb stops on the faulting line, so bt and v work at the exact moment of the crime.

Terminal first aid

In zsh, the shell on your Mac, the first two rows last only until the next prompt: zsh switches echo and line mode back on for itself before printing it. In bash they stay until you fix them. In either shell, a program started on the same command line (./build/snake; cat) finds exactly what the last one left behind, which is how you check a guard.

Settings belong to one terminal window. Closing the window always throws them away, and a new window always starts normal.

Glossary

  • Arrow-key escape sequence: the three bytes a terminal sends for an arrow key, 27 [ and a letter (A up, B down, C right, D left).
  • Backtrace: the list of function calls that led to where the program is stopped, innermost first (bt).
  • Breakpoint: a place where the debugger stops the program. Conditional breakpoint: one that stops only when an expression is true.
  • Canonical mode (line mode): the terminal collects a whole line, with editing, and hands it over on Enter.
  • Case label: case Value: inside a switch; several labels can share one statement.
  • Constructor: the function, named after the struct, that runs when an object is created. Destructor: the one named ~Name that runs when it dies.
  • Deadline: the moment by which a tick's work should be done; the next tick starts there, not "150 ms after this one ended".
  • Deque: std::deque, a double-ended queue, cheap to grow and shrink at both ends, stored in fixed-size blocks.
  • Designated initialiser: Date d{.year = 2026, .month = 11}, naming the members you set.
  • Developer Mode: the macOS setting that lets debuggers control your programs without asking each time (DevToolsSecurity).
  • Echo: the terminal printing what you type, as you type it.
  • Enumerator: one of the named values of an enum (Light::Red). enum class: an enum whose values are scoped and never turn into numbers by themselves.
  • Fallthrough: running on from one case into the next because a break or return is missing.
  • Frame (in lldb): one function call's place on the call stack, with its own variables.
  • Guard: an object whose only job is to undo something when it dies: restore a setting, show the cursor, close a file.
  • Jump table: a switch compiled into one lookup and one jump. Compare chain: a switch compiled into one test per case.
  • Late tick (dropped frame): a tick whose work took longer than its budget.
  • Lifetime: the stretch of the run during which an object exists. Scope: the stretch of the source code in which a name can be used.
  • Member: one of the named parts of a struct (d.month).
  • Optional: std::optional<T>, either a T or nothing (std::nullopt).
  • RAII (resource acquisition is initialisation): tying a resource to an object, acquired in its constructor and released in its destructor, so it can never be forgotten.
  • Raw mode: canonical mode and echo off, so each key reaches the program at once and silently.
  • Signal: a message from the operating system to a program; Ctrl-C sends SIGINT. Signal handler: a function of yours that runs when one arrives.
  • Sliding window: a fixed-length run of the most recent items, one added at one end and one dropped at the other.
  • Struct: a type you define as a group of named members.
  • termios: the struct that holds a terminal's settings, read with tcgetattr and written with tcsetattr.
  • Tick: one step of the game, and the fixed slice of time it gets.
  • VMIN and VTIME: two of the terminal's control values, saying how many bytes a read waits for and for how long.

What week 4 brings (Tetris)

A preview, so you recognise the names; nothing here is needed this week.

Classes with invariants. A Tetris piece must always be one of seven shapes in one of four rotations. A class is a struct whose members are hidden behind functions of its own, so nothing outside can put it into a state that breaks that promise. Your Game is a struct: anything can set score to -5. Next week you will see when that matters.

Constructors and destructors, in depth. This week you wrote one constructor and one destructor, for a guard. Next week, constructors that take arguments and check them, and the members the compiler writes for you when you write none.

Copy and move, and a tiny Vec2. What happens when you copy a RawTerminal? Two destructors restore the same settings. Harmless here, a disaster for a guard that frees memory. Week 4 explains copying and moving, and how a type can forbid being copied. You will also give a two-number type its own + and ==.

std::array and rotation. A piece is four cells in a fixed-size array; rotating it is multiplying each cell by a 2 by 2 matrix. In week 16 the same rotation, applied to pairs of numbers inside a model, is rotary position embedding.

Check yourself

error: invalid operands to binary expression ('Reading' and 'Reading'). What did you write, and what are your two ways out?

Answer

An operator, probably ==, between two values of your own struct Reading, which knows no operators. Either compare the members you care about yourself, or add bool operator==(const Reading&) const = default; to the struct so the compiler compares every member.

A forty-line error ends somewhere inside format_functions.h. Which two words do you look for?

Answer

Your own type's name, inside formatter<YourType, char>: it means you passed a value of your struct to std::print or std::println, which cannot turn it into text. Print its members, or a string built from them.

Why is a switch over an enum class better without a default?

Answer

Because then -Wswitch warns about every enumerator the switch does not handle. With a default, an enumerator added later silently goes to the default, and nothing tells you.

Every file compiled, and then: Undefined symbols for architecture arm64: "read_keys()". Where is the mistake?

Answer

Not in the code, but in the build: the file that defines read_keys (terminal.cpp) was not compiled into this program. Check the add_executable line, or the files on your clang++ command.

In lldb, what is the difference between next and step on a line that calls tick?

Answer

next runs the whole line, including all of tick, and stops at the following line. step goes into tick and stops at its first line, so you can follow it.

In bash, your game crashed and the terminal does not echo. Which command do you type, and why blind? And why does the same crash in zsh leave only a missing cursor?

Answer

reset (or stty sane) and Enter. You type it blind because echo is exactly the setting the crash left off; the shell still receives your keys, it just does not show them. zsh switches echo and line mode back on before every prompt, so in zsh only the cursor, which no shell setting covers, stays hidden: tput cnorm.
